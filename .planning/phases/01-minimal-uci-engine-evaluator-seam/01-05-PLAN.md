**As a** chess GUI or UCI test harness driving ANCE over stdin/stdout, **I want to** complete the handshake and receive exactly one legal `bestmove` for every `go` — even through a swappable evaluator — **so that** I can play a complete, legal game and confirm ANCE reliably beats a random-mover opponent.

<objective>
Build the self-play harness that pits ANCE's real search+eval (in-process,
not over a UCI pipe — this is a measurement tool, not a protocol test)
against a uniformly-random legal-move opponent, and prove ANCE wins all
100 games in a fixed, seeded 100-game run.

Purpose: TOOL-02 is one of the milestone's two hard proof points (with
TOOL-01). A correct engine with a full evaluator should never need a draw
against a purely random opponent — this plan encodes "beats" as
wins == 100, losses == 0, per 01-RESEARCH.md's Wave 0 Gaps guidance.
Cross-AI review flagged this strict target as potentially brittle at
shallow, non-pruned search depth; this plan's judgment call is to keep
the strict 100/100 target (a loss to a random mover is always a bug) but
make it robust by giving the gauntlet its own, deeper `GAUNTLET_SEARCH_DEPTH`
(decoupled from the interactive `DEFAULT_DEPTH`) and by recording
seed/result/terminal-FEN diagnostics for any non-win game.

Output: `ance/tools/random_mover_gauntlet.py` plus a `slow`-marked pytest
that asserts the 100/100 result, with built-in failure diagnostics.
</objective>

    `GAUNTLET_SEARCH_DEPTH = 4` — a constant deliberately decoupled from
    `ance.search.negamax.DEFAULT_DEPTH` (documented inline: the
    interactive default is tuned for sub-second GUI responsiveness in
    Plans 01-03/01-04 and may be lowered to 2; the gauntlet is an offline

    100/100-brittleness finding without weakening interactive
    responsiveness). Defines
    `def run_gauntlet(n_games: int, ance_depth: int, evaluator: Evaluator) -> dict`
    that loops `game_index in range(n_games)`, alternates
    `ance_plays_white = game_index % 2 == 0` for color fairness, calls
    `play_game(ance_depth, evaluator, ance_plays_white, seed=game_index)`
    to get a `GameResult`, tallies the outcome into
    `{"wins": int, "losses": int, "draws": int}` from ANCE's perspective
    (a `"1-0"` result counts as a win when ANCE played White and a loss
    when ANCE played Black, and symmetrically for `"0-1"`; `"1/2-1/2"`
    always counts as a draw), and — for any game that is not a win —
    appends `{"seed": game_index, "result": game_result.result, "terminal_fen": game_result.terminal_fen}`
    to a `non_win_games: list[dict]` that is included in the returned
    dict alongside the tallies. Register the test with `@pytest.mark.slow`

    assertion's failure message embedding `result["non_win_games"]`.

    300, passed through from `play_game`) in case of a pathological long
