## Phase Goal

**As a** chess player running ANCE under a real clock in a GUI, **I want to** play blitz games against an engine that searches efficiently and manages its own time, **so that** games are decided by chess strength rather than shuffling, shallow search, or time forfeits.

<objective>
Implement SRCH-05: a Zobrist-keyed transposition table with correct fail-soft bound flags, depth-preferred replacement, ply-adjusted mate scores, and ucinewgame clearing — integrated into negamax with a single Zobrist computation per node. After this plan a GUI user sees the engine reach greater depth in the same think time and report stable mate scores.

Purpose: The TT is staged before move ordering by roadmap decision (ordering multiplies on TT hash moves); D-01..D-06 lock its shape.
Output: `ance/search/transposition.py`, negamax probe/store integration, loop.py wiring, and the D-22 mate-stability tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UCI stdin → TT lifetime | ucinewgame/position commands control per-game state; stale entries must not leak across games |
| stale worker → shared TT | a bounded-join survivor may write entries concurrently with its replacement |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-03a | Tampering | wrong mate distances from ply mixing | high | mitigate | score_to_tt/score_from_tt conversion lives only at the TT module boundary; D-22 stability test pins it empirically across depths |
| T-03-03b | Information Disclosure | cross-game state leakage | high | mitigate | handle_ucinewgame clears the whole table (D-06); integration test asserts post-clear node counts equal cold counts |
| T-03-03c | Tampering | index-collision score corruption | high | mitigate | Full stored-key comparison on every probe; unit test constructs colliding keys and asserts rejection |
| T-03-03d | Tampering | stale-worker concurrent writes | medium | accept | Tuple entries + atomic single-slot list assignment under the GIL; worst case is a stale well-formed entry tolerated by depth-preferred replacement (RESEARCH Pitfall 7) — no hot-path locking |
| T-03-03e | Denial of Service | unbounded memory | medium | mitigate | Fixed 2^20 slot count (D-01); clear() reallocates rather than grows; documented ~250 MB saturation ceiling on 24 GB |
| T-03-03f | Tampering | GHI (path-dependent draws vs position keys) | low | accept | Draw check runs before probe (locked ordering); residual graph-history inaccuracy is accepted industry-wide (RESEARCH Pitfall 2) |
