## Phase Goal

**As a** developer preparing Phase 5's NNUE swap-in, **I want to** turn Stockfish-labeled chess positions into a validated, exported `(768→256)×2→1` weights file via an offline PyTorch/MPS pipeline, **so that** Phase 5 can load real trained weights behind the untouched `evaluate()` seam and prove a measurable Elo gain over the handcrafted baseline.

> Note: see Plan 04-01 for the full discrepancy note on why this user-story framing is derived rather than quoted verbatim from ROADMAP.md.

> MVP vertical-slice note: this plan thickens the pipeline with one real ingredient — genuine Stockfish labeling — while Plan 04-02's synthetic-data slice keeps proving the mechanism independently in parallel.

    - Test 2: the depth benchmark returns a strictly positive positions-per-second rate for every candidate depth tried.
    - Both tests must skip cleanly (never fail) if the `stockfish` binary is not on PATH.
  </behavior>
  <action>
Create `training/label/stockfish_labeler.py`, docstring citing TRN-01/D-02. `label_position(engine: chess.engine.SimpleEngine, fen: str, depth: int) -> dict`: builds `chess.Board(fen)`, calls `engine.analyse(board, chess.engine.Limit(depth=depth))`, reads `info["score"].relative` (STM-relative — this is the "normalized UCI cp, never internal eval" requirement, satisfied by using `chess.engine`'s own parsed `PovScore` rather than any raw-output regex path per Pitfall 2), and returns `{"fen": fen, "mate": score.mate(), "cp": None}` if `score.is_mate()` else `{"fen": fen, "mate": None, "cp": score.score()}`.

`run_labeling(stockfish_path: str, fens: list[str], depth: int) -> list[dict]`: opens `chess.engine.SimpleEngine.popen_uci(stockfish_path)` as a context manager and calls `label_position` for every FEN, returning the list of result dicts.

`run_depth_benchmark(stockfish_path: str, fens: list[str], candidate_depths: list[int]) -> dict[int, float]`: for each depth in `candidate_depths`, times (via `time.perf_counter()`) a `run_labeling` call over the first 20 entries of `fens` (or all of them if fewer), and returns `{depth: len(subset) / elapsed_seconds}` — turning Open Question #1's throughput unknown into a measured value the caller can use to pick a depth that fits the D-08 wall-clock budget.

`record_labeling_command(stockfish_path: str, depth: int) -> str`: returns `f"{stockfish_path} -- chess.engine.SimpleEngine.analyse(depth={depth})"`.

`run_and_record_labeling(stockfish_path: str, fens: list[str], depth: int, manifest_path: str) -> list[dict]`: a thin convenience wrapper that calls `run_labeling`, then `training.run_manifest.record_event(manifest_path, event="fresh_labeling", command=record_labeling_command(stockfish_path, depth), depth=depth, n_positions=len(fens))` — one call site for D-02's "exact command recorded" requirement, not scattered prints across callers.

Write `tests/training/test_stockfish_labeler.py` with a module-level `pytest.mark.skipif(shutil.which("stockfish") is None, reason="stockfish binary not on PATH")` so the whole file skips (never errors) if Stockfish is absent. `test_label_position_returns_cp_or_mate_favoring_white()`: label the FEN for a position where white is up a full queen at `depth=6`, assert the result has a non-null `cp` or `mate` and that value's sign favors white. `test_depth_benchmark_returns_positive_rates()`: run `run_depth_benchmark` over 5 FENs from `training.label.position_source.generate_position_set(n_games=1)` at `candidate_depths=[6, 8]`, asserting every returned rate is strictly greater than 0.
  </action>
