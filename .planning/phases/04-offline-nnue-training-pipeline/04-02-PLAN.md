## Phase Goal

**As a** developer preparing Phase 5's NNUE swap-in, **I want to** turn Stockfish-labeled chess positions into a validated, exported `(768→256)×2→1` weights file via an offline PyTorch/MPS pipeline, **so that** Phase 5 can load real trained weights behind the untouched `evaluate()` seam and prove a measurable Elo gain over the handcrafted baseline.

> Note: see Plan 04-01 for the full discrepancy note on why this user-story framing is derived rather than quoted verbatim from ROADMAP.md.

> MVP vertical-slice note: this plan delivers the phase's core thin slice — model → smoke-train → export → zero-torch load — on synthetic data. It is the first "runnable end-to-end result" the planning brief calls for; Plans 04-03 through 04-07 thicken it with real data.

  <action>
Create `training/train.py`, docstring citing TRN-03/TRN-05/D-09. At module import time, call `os.environ.setdefault("PYTORCH_ENABLE_MPS_FALLBACK", "1")` (per project CLAUDE.md — lets unimplemented MPS ops degrade to CPU rather than crash). Define `wdl_loss(model_out_cp: torch.Tensor, eval_cp: torch.Tensor, game_result: torch.Tensor, has_result: torch.Tensor, k: float, lambda_: float = 0.5) -> torch.Tensor` exactly per 04-RESEARCH.md Pattern 4: `wdl_model = torch.sigmoid(model_out_cp / k)`, `wdl_eval_target = torch.sigmoid(eval_cp / k)`, `effective_lambda = torch.where(has_result.bool(), full_like(lambda_), full_like(1.0))`, `target = effective_lambda * wdl_eval_target + (1 - effective_lambda) * game_result`, return `((wdl_model - target) ** 2).mean()`.

Define `preflight_mps_gate() -> str`: calls `training.mps_gate.select_device()`, then `training.mps_gate.cpu_vs_mps_parity_check(device, model_factory=training.model.NNUE)` — this is the real-architecture invocation of Plan 04-01's generic gate, and functions as this training entrypoint's first call, satisfying D-09's "very first training-harness task" requirement at the point real training actually begins. Returns the selected device string.

Keep every tensor operation in this file (and in `training/model.py`) at float32 precision throughout, consistent with the project's MPS constraints (no double-precision casts, no automatic-mixed-precision helpers) — express this constraint in each file's module docstring using prose, not by naming the specific disallowed API calls verbatim in a code comment (the dedicated structural test below enumerates the exact disallowed identifiers itself).
