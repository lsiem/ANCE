## Phase Goal

**As a** developer preparing Phase 5's NNUE swap-in, **I want to** turn Stockfish-labeled chess positions into a validated, exported `(768→256)×2→1` weights file via an offline PyTorch/MPS pipeline, **so that** Phase 5 can load real trained weights behind the untouched `evaluate()` seam and prove a measurable Elo gain over the handcrafted baseline.

> Note: `.planning/ROADMAP.md`'s Phase 4 `**Goal:**` line is written as a capability statement, not literally in "As a / I want to / so that" form — this phase is an offline data/ML pipeline with no end-user in the product sense (its consumer is Phase 5, and ultimately the engine). This framing is derived directly from that goal plus the phase's 5 success criteria and TRN-01…TRN-05 (no new scope invented), following the same discrepancy-handling precedent established in Plan 01-01. See the planner's return message for this note surfaced to the orchestrator.

> MVP vertical-slice note: for this offline pipeline, a "vertical slice" is a thin end-to-end path through the whole mechanism (tiny labeled sample set → encode features → train a handful of steps on CPU-or-MPS → export `.safetensors` → numpy-only roundtrip-load and validate) rather than a user-facing UI/API/DB slice. This plan and Plan 04-02 deliver that thin slice first, on synthetic data. Plans 04-03 through 04-07 thicken it with real Stockfish labeling, real Lichess ingestion, real K-fit calibration, and finally the real wall-clock-capped run.
