## Phase Goal

**As a** developer preparing Phase 5's NNUE swap-in, **I want to** turn Stockfish-labeled chess positions into a validated, exported `(768→256)×2→1` weights file via an offline PyTorch/MPS pipeline, **so that** Phase 5 can load real trained weights behind the untouched `evaluate()` seam and prove a measurable Elo gain over the handcrafted baseline.

> Note: see Plan 04-01 for the full discrepancy note on why this user-story framing is derived rather than quoted verbatim from ROADMAP.md.

> MVP vertical-slice note: this plan thickens the pipeline with the bulk Lichess data stream and the dataset-assembly stage (merge/dedup/split) that both label sources ultimately feed.

## Artifacts this phase produces

*(Full phase-wide artifact inventory — identical across every plan in this phase. See Plan 04-01 for the complete list and attribution. This plan builds: `training/data/lichess_ingest.py`, `training/data/merge.py`, `training/data/split.py`, and their three test files.)*

<objective>
Build the Lichess bulk-ingestion stream with the mandatory sign correction (D-01, Pitfall #3), the FEN-dedup merge step that combines it with the fresh-labeling stream from Plan 04-03, and the by-game train/val split with its automated disjointness assertion (TRN-02, D-03). Wrap ingestion defensively so a malformed corpus entry never aborts a multi-hour run (T-4-01).

Purpose: TRN-02 requires an automated, load-bearing check that no FEN leaks across the train/val boundary — this is the single most common NNUE data-leakage bug (Pitfall #12/#5), and this plan is where that discipline is enforced structurally, not just documented.
Output: `training/data/lichess_ingest.py`, `training/data/merge.py`, `training/data/split.py`, each covered by passing tests using small synthetic fixtures (no multi-GB download required for these unit tests).
</objective>
